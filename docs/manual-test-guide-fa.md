# راهنمای تست عملی Egress Eye 1.0.0 — کاندیدای انتشار

این نسخه برای سایت آزمایشی تک‌سایته است. پیش از تست از سایت و دیتابیس نسخهٔ پشتیبان بگیرید. آزمایش‌های خودکار جای دیدن و کار کردن با رابط واقعی را نمی‌گیرند. این راهنما هنوز توسط مالک اجرا نشده است؛ نتیجه، تاریخ، نسخه‌ی وردپرس و PHP و موتور دیتابیس را ثبت کنید و موارد ناموفق را گزارش دهید.

## نصب و صفحهٔ مدیریت

۱. پس از اجرای موفق CI و Plugin Check، artifact همان اجرا و هش اعلام‌شدهٔ بسته را کنترل کنید؛ فقط فایل `egress-eye.zip` داخل آن را در «افزونه‌ها ← افزودن ← بارگذاری افزونه» نصب و فعال کنید. فایل فشردهٔ بیرونی artifact را به وردپرس ندهید. تا پیش از اجرای بررسی رسمی روی همین بسته، آن را بررسی‌شده تلقی نکنید.
۲. با حساب مدیر، «ابزارها ← Egress Eye» را باز کنید. برای فارسی، زبان سایت را فارسی کنید؛ چیدمان راست‌به‌چپ و متن فارسی باید دیده شود.
۳. قبل از ثبت درخواست کند، جدول خالی طبیعی است. فقط درخواست‌های مسدودکنندهٔ HTTP API وردپرس با زمان حداقل یک ثانیه ثبت می‌شوند؛ تعداد و میانگین مربوط به همین درخواست‌هاست.

## ساخت یک درخواست کند روی همان سایت

کد زیر ابزار موقت تست است و در ZIP افزونه وجود ندارد. در فایل‌منیجر هاست، پوشهٔ `wp-content/mu-plugins` را بسازید و کد را در فایل `egress-eye-manual-fixture.php` بگذارید. فقط روی سایت آزمایشی استفاده کنید و پس از تست فایل را حذف کنید.

```php
<?php
// Temporary manual fixture; remove after testing. Never ship with Egress Eye.
defined( 'ABSPATH' ) || exit;

add_action( 'init', static function () {
    $key = 'egress-eye-manual-57b32c6dff61460ab480949e';
    if ( isset( $_GET['ee_manual_slow'] ) && is_string( $_GET['ee_manual_slow'] ) && hash_equals( $key, $_GET['ee_manual_slow'] ) ) {
        usleep( 1500000 );
        header( 'Content-Type: text/plain; charset=utf-8' );
        echo 'Local slow fixture';
        exit;
    }
} );

add_action( 'admin_notices', static function () {
    if ( ! current_user_can( 'manage_options' ) ) {
        return;
    }
    $link = wp_nonce_url( admin_url( 'admin-post.php?action=ee_manual_request' ), 'ee_manual_request' );
    echo '<div class="notice notice-info"><p><a href="' . esc_url( $link ) . '">ساخت درخواست کند برای تست Egress Eye</a></p></div>';
} );

add_action( 'admin_post_ee_manual_request', static function () {
    if ( ! current_user_can( 'manage_options' ) || 'GET' !== $_SERVER['REQUEST_METHOD'] ) {
        wp_die( 'Access denied' );
    }
    check_admin_referer( 'ee_manual_request' );
    $url = add_query_arg( 'ee_manual_slow', 'egress-eye-manual-57b32c6dff61460ab480949e', home_url( '/' ) );
    $response = wp_remote_get( $url, array( 'timeout' => 10, 'blocking' => true ) );
    $message = is_wp_error( $response ) ? 'درخواست عبور نکرد؛ وضعیت میزبان یا امکان اتصال سایت به خودش را بررسی کنید.' : 'درخواست انجام شد؛ جدول Egress Eye را بررسی کنید.';
    wp_die( esc_html( $message ), 'Egress Eye manual test', array( 'back_link' => true ) );
} );
```

روی لینک «ساخت درخواست کند…» در پیشخوان کلیک کنید و سپس صفحهٔ Egress Eye را باز کنید. میزبان خود سایت و مدت حدود ۱٫۵ ثانیه یا بیشتر باید دیده شود. اگر هاست اتصال سایت به خودش را نمی‌پذیرد، این آزمایش را روی یک محیط محلی با loopback فعال انجام دهید؛ خطای اتصال، به‌تنهایی شکست افزونه نیست. درخواست‌های مرورگر، cURL مستقیم و درخواست‌های سریع‌تر در این جدول قرار نمی‌گیرند.

## قطع، وصل و تاریخچه

۱. برای میزبان سایت هشدار برجسته دیده می‌شود. تأیید اضافه را تیک بزنید و «قطع کن» را بزنید. این کار ممکن است کرون و کارهای سایت را متوقف کند؛ فقط در محیط آزمایشی انجام دهید.
۲. دوباره لینک درخواست کند را بزنید. این بار درخواست باید مسدود شود. برای جلوگیری از قفل ماندن سایت، بلافاصله در صفحهٔ افزونه «وصل کن» را بزنید و آزمایش را تکرار کنید؛ باید عبور کند.
۳. تاریخچهٔ صفحه باید اقدام، میزبان، شناسهٔ کاربر مدیر و زمان UTC را نشان دهد. وضعیت قبل و بعد در رکورد دیتابیس ذخیره و با تست خودکار بررسی می‌شود. ارسال دوبارهٔ همان وضعیت نباید تاریخچهٔ تکراری بسازد.
۴. قطع برای میزبان دقیق است؛ زیردامنه‌ها و IP متناظر خودکار قطع نمی‌شوند. مقصد ریدایرکت تضمین نمی‌شود. «مسئول احتمالی» فقط حدس است.

## دسترسی و داده‌ها

- با حساب مشترک/غیرمدیر، صفحه و اقدام قطع/وصل نباید در دسترس باشد. آزمایش nonce، GET و XSS با تست‌های خودکار CI انجام می‌شود؛ نیازی به دستکاری کد تولیدی نیست.
- وقتی ۵۰۰ میزبان جا را پر کنند، پیام ظرفیت نمایش داده می‌شود. وصل کردن فوراً جا باز نمی‌کند؛ نگهداری باید میزبان قدیمی و وصل را حذف کند.
- روی MyISAM، ثبت و نمایش داده‌ها ادامه دارد، اما قطع و وصل انجام نمی‌شود؛ تغییر وضعیت و تاریخچه باید با هم ذخیره شوند. برای فرمت InnoDB از پشتیبانی هاست کمک بگیرید. برای تست دستی موتور جدول‌ها را روی سایت اصلی عوض نکنید؛ چهار حالت با دیتابیس واقعی در CI آزموده می‌شوند.
- پس از ثبت نمونه و یک قطع/وصل، افزونه را غیرفعال و دوباره فعال کنید؛ داده‌ها باید باقی بمانند. سپس در سایت آزمایشی از صفحه‌ی افزونه‌ها «حذف» را بزنید. سه جدول با نام پایان‌یافته به `http_diag_domains`، `http_diag_events` و `http_diag_audits`، optionهای `egress_eye_`، پیام موقت مدیر و همه‌ی cronهای `egress_eye_retention` باید حذف شوند. برای مشاهده‌ی دیتابیس/cron از پشتیبانی هاست کمک بگیرید. نصب تازه باید صفحه‌ی خالی بسازد؛ داده‌ی قبلی نباید بازگردد.

پس از پایان، فایل موقت را حذف کنید و میزبان سایت را در وضعیت وصل باقی بگذارید. صفحهٔ افزونه فایل خارجی، CDN یا سرویس تحلیل ندارد؛ درخواست بالا فقط از کد موقت تست به خود سایت ایجاد می‌شود.
